## 学习目标（一天结束你要能说清）
1. 用 AI 把「公开养老信息」变成一份「可读、有结构、经得起追问」的月度简报片段
2. 内化一条运营铁律：所有「率」配结构读，否则自我麻醉
3. 能讲清「公开 / 推演 / 模拟」三种数据性质的区别，面试不慌

## 前置（已在周一二完成，今天直接调用）
- 周一《运营模块清单》给了 5 维度 + 预警线 + 暴露指标 → 这是简报的「评分尺」
- 周二角色演练练了「家属关系 / 合规」软模块 → 今天简报第 4、5 维度能用上
- 简报模板（7-23）给了字段表 + 预警线 + 院长提醒注释

## 今日三步（约 1.5h）

### 步骤一 · 定场景与维度（15min）
- 场景锁定：阳光老人家·颐乐和睦（社区 / 政府系兜底型，三业态里你的「进场票」）
- 五维度照搬模板：入住/服务覆盖率、服务人次、补贴到账、投诉与满意度、安全事件
- 关键动作：先把「预警线」从模板抄进每维度表头，后面填数才知道什么叫「踩线」

### 步骤二 · 中文源核实公开数字（45min）
- 用政府 / 媒体中文源（用户已授权，不绕英文源）
- 抓取核心数：拱墅区 60+ 户籍 9.4 万占 25%、站点 52 家 / 2020 全覆盖、颐乐和睦 2019 开街、日均来访 5000+；杭州市 2024 底 60+ 227.27 万、全城通助餐 1500 余家优惠 1.1 亿、重阳分累计近 15 亿；政策 杭民发〔2024〕142号补贴标准
- 每个数字打性质标签：`[公开·拱墅区]` / `[公开·杭州市]` / `[公开·政策]` / `[推演]` / `[模拟]`
- 单站点真实运营数公开缺失 → 用「全区均值下推」并明确标 `[推演]`，不假装精确

### 步骤三 · 套模板生成 + 辩证复盘（30min）
- 让 AI 套模板生成「真实感片段版」，每个数带来源与年份口径
- 你做三件事：
  a. 写「院长读数」：每个维度讲清数字背后藏的雷（例：满意度 92% 但最难群体 85%）
  b. 应用三层底稿：第一性原理 / 反馈回路 / 指标陷阱
  c. 找一处「指标陷阱」活教材：拱墅「志愿服务满意率 100%」= 样本偏差典型

## 验收标准（做完对照）
- [x] 简报五维度都填了真实感数字，且每格有性质标签（已产出：`[[社区养老简报样稿_阳光老人家示意]]`）
- [x] 单站点缺失数据用 `[推演]` 而非编造，文末写清来源与年份
- [x] 「院长读数」+ 三层底稿写完，能口头讲 3 分钟
- [x] 标注「模拟基于公开信息，非真实填报」

## 辩证提醒
- 真实感 ≠ 真实填报。能说清「从哪来、缺在哪、什么年份」，比堆精确数字更有竞争力
- 社区养老数据「全区有、单站点无、停在 2019 开街期」本身是真问题，作品集可点出
- 这一步是第 4 周「AI 变生产力」的落地：AI 不是替你想，是替你把杂乱信息变洞察
